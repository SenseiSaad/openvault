## 2. Policy area: Version

- Release notes are published for every production version.
- New features are listed with a short customer-facing description.
- Fixes reference the internal ticket identifier.
- Deprecations are announced at least one release in advance.
- Migration guides accompany breaking changes.
- All version records are reviewed by Group Product at each quarterly cycle.
- Regional leads in Karachi confirm local applicability of version.
- Questions about version are logged in the policy query register.
- Any change to version requires an impact note and an owner sign-off.
- Supporting templates for version are published on the intranet.
